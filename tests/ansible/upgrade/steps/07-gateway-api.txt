# Gateway API CRDs v1.2.1 -> v1.5.1 (before Istio 1.30). v1.5.1 still serves every version v1.2.1 did (v1, and v1beta1
# of GatewayClass/Gateway/HTTPRoute/ReferenceGrant), so the Istio running at this point (1.29.8, which pins v1.4.0)
# keeps what it reads; it adds BackendTLSPolicy, ListenerSet, TLSRoute and a safe-upgrades ValidatingAdmissionPolicy.
# Applied server-side by the kubeadm playbook's task (host-side). At the rollout gateway_api_version becomes v1.5.1.
# ONE-WAY: the safe-upgrades policy refuses any gateway.networking.k8s.io CRD of bundle v1.0-v1.4 - going back means
# deleting that policy first, and a setup-kubeadm run with the old default (v1.2.1) fails until the default moves.
# outage: none - CRDs only
# abort: one-way: v1.5's safe-upgrades policy refuses the older CRDs, and setup-kubeadm.yml refuses an older bundle
# (tasks/no-downgrade.yml); back only by hand, removing that policy first - not written down, not rehearsed - or the
# Wave 0 etcd snapshot restored into the node's etcd (only its restore into a scratch data directory is rehearsed)
# one-way: etcd's snapshot backed up into the Pi store before the CRDs change (seconds)
wave0 etcd
crd gateway-api v1.2.1 => crd gateway-api v1.5.1
playbook setup-kubeadm.yml --tags gateway-api -e gateway_api_version=v1.5.1
# the playbook defaults this step moves (scripts/upgrade-defaults.py; production commits them after the step)
default deploy/ansible/playbooks/setup-kubeadm.yml: gateway_api_version: "v1.2.1" => gateway_api_version: "v1.5.1"
